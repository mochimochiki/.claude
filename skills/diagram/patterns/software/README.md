# ソフトウェアの設計と実装の作例

目次は `../README.md` の「ソフトウェアの設計と実装(記法あり)」にある。ここには、記法の定義を優先して `SKILL.md` の規則を外した箇所と、確かめた資料だけを書く。題材はすべて架空で、各 SVG の `<desc>` にそう書いた。

## 記法を優先して外した規則

- **DFD のラベル**: DFD はデータフローに流れるデータの名前(名詞)を書く記法なので、矢印に動詞のラベルを付ける規則を外した。
- **配置図の通信経路**: UML の通信経路は矢じりの無い線で、ラベルは通信の種類のステレオタイプ(«HTTPS» など)である。ゾーンの帯は UML の記号ではない注記である。
- **攻撃ツリーの線**: 親と子を結ぶ線は流れではなく分解なので、矢じりを付けない。
- **C4 の色と形**: C4 モデルは色と形を決めていないので、凡例を必ず付ける。
- **タイミング図の継続時間制約**: UML の定義では区間(`{d..3*d}` など)で書く。作例では `{10 秒}` と省略し、そのことを desc に書いた。
- **ER 図の線種**: 識別関連と非識別関連を実線と破線で分ける流儀はツールによって違うので、作例では区別していない。
- **字数**: 多くは詳細図なので、`scripts/check.py` の字数の指摘は意図して外したものとして読む。

## 確かめた資料

- UML: OMG Unified Modeling Language 2.5.1
- C4 モデル: c4model.com
- DFD: DeMarco と Yourdon の記法。脅威の分類は Microsoft の STRIDE、信頼境界の描き方は Microsoft Threat Modeling Tool と OWASP の脅威モデリング
- ER 図: IE 記法(crow's foot)
- ユーティリティツリー: SEI の ATAM。品質特性の名前は JIS X 25010:2013
- 攻撃ツリー: Schneier「Attack Trees」(Dr. Dobb's Journal, 1999)
