# 講義(lecture)

読み手を、図と結果を自分の言葉で説明できるところまで連れていく。用語集と図で説明し、メインの図の上で確認テストを出して理解を確かめる。ここに書く決まりは講義のときだけ当て、ふつうの図には当てない。

## 材料

- いまのセッションの会話・作業・記録、リポジトリの文書、そのセッションで描いた図を使う。
- 用語は `references/term.md` の形で作る。
- ページは `assets/lecture-template.html` をひな形にする。

## 図

- **メインの図**: 講義の中心になる全体図を 1 枚決める。テストの多くをこの図の上で出すので、問いたい要素がこの図に載っている必要がある。そのため、メインの図は多くの場合、正確さを優先した詳細図になる。
- **補助の図**: メインの図の一部を拡大して説明するときだけ足す(パターン帳の「ズーム」の関係)。足す前に、メインの図に入れられないかを一度考える。図の枚数は少なく保つ。
- どの図も `SKILL.md` の規則と「描いたあとの確認」に従う。

## 印の層

メインの図の上に、透明な層を重ねる。層には「図のこの範囲は何か」を表す印を置く。印は SVG の座標(x・y・幅・高さ)で書き、層は図と同じ `viewBox` を持つので、表示の大きさが変わっても位置がずれない。

印の層は、次の 3 つに使う。

- **用語へのリンク**: 印をクリックすると、用語集の対応するカードへ移る。
- **問題で光らせる場所**: 問題を出すとき、問題が指す範囲に枠を出す。
- **ラベルを隠す覆い**: 「ここに入る語は？」と問うとき、その範囲を塞ぐ。

印の範囲は、図を描いたときの座標から取る。部品の箱の座標をそのまま使い、目分量で書かない。

## ページの構成

次の順に並べる。

1. **結論**: 3〜5 行。行ごとに「動いた」「注意」「未確認」のような状態の印を付ける。
2. **なぜその話をしたか**: 背景と、何を確かめたか・決めたか。
3. **メインの図と確認テスト**: メインの図、図の読み方、テストを始めるボタン。
4. **用語**: 用語集を段階順に置く。
5. **分かったこと**: 1 つずつ節にし、補助の図があれば図と読み解きを置く。節の最後に「つまり」で始まる 1〜2 文を置く。
6. **残っていること**: 確かめていないことと、次に決めること。
7. **環境と出典**: 版、日付、記録の場所。

- 図の前後の本文では、図の題を言い換えずに、図を読む手がかりを書く。
- 確かめていないことを、分かったことの節に混ぜない。推定で書いた所は、推定と書く。

## 確認テスト

テストはメインの図に付ける。メインの図の横の「この図でテスト」を押すと始まり、問題はメインの図の下に 1 問ずつ出る。

### 問題の数と順

- **基本の 5 問**: 先に出す。その話の芯を思い出させる問題にする。外すと話全体が崩れる事実と判断を選ぶ。
- **発展の 5 問**: 基本の 5 問に答え終えてから開けるようにし、解くかは読み手が選ぶ。推論の問題を 2 問以上入れる。
- **外へ飛ばす問題**: 発展の中に 1 問だけ、セッションとリポジトリの外の場面と比べさせる問題を入れる。どこが同じ原理で、どこがその場面に固有かを考えさせる。ほかの問題は、セッションとリポジトリから出す。
- 10 問のうち半分以上は、メインの図の印を使う(光らせる、隠す)。補助の図の内容や、図に載らない判断を問う問題は、光らせずに出してよい。

### 答え方

- **思い浮かべる問題**: 答えを頭で思い浮かべてから「答えを見る」を押させ、「できた」「あいまい」「できなかった」で自己採点させる。文字は入力させない。
- **選択式**: 3〜4 択。選んだらすぐ正誤と解説を出す。

### 選択肢と解説

- 誤りの選択肢は、そのセッションで実際に起きうる勘違いから作る。確かめる前なら思い込みやすい誤りを使い、数合わせの誤答を並べない。
- 解説には、なぜその答えかを 1〜3 文で書き、関係する用語のカードへのリンクを付ける。
- 最後に、正答と自己採点の数をまとめ、間違えた問題と「あいまい」の問題に関係する用語へのリンクを並べる。結果はページの中だけに出し、保存しない。

## ひな形の埋め方

`assets/lecture-template.html` の中で、`<!-- 埋める: … -->` の印がある所を書き換える。印の層と問題は、ページの末尾の `<script type="application/json" id="lecture-data">` にまとめて書く。形は次のとおりで、ひな形の中の例を消してから書く。

```json
{
  "viewBox": [0, 0, 640, 540],
  "marks": [
    { "id": "broker", "x": 40, "y": 176, "w": 240, "h": 56, "term": "broker", "label": "ブローカー" }
  ],
  "questions": [
    {
      "level": "basic",
      "type": "recall",
      "prompt": "ワーカーがブローカーに送るキーは何か。",
      "highlight": ["worker"],
      "mask": [],
      "answer": "偽物のキー。本物への付け替えはブローカーが行う。",
      "terms": ["broker", "byok"]
    },
    {
      "level": "advanced",
      "type": "choice",
      "prompt": "ループバックの例外を付けた箱から届くのはどこか。",
      "highlight": [],
      "mask": [],
      "choices": ["ブローカーのポートだけ", "127.0.0.1 のすべてのポート", "外のホスト"],
      "correct": 1,
      "explain": "例外は箱ごとに 127.0.0.1 への接続を許すだけで、ポートは選べない。",
      "terms": ["loopback-exempt"]
    }
  ]
}
```

- `viewBox` はメインの図の SVG と同じ値にする。
- `marks` の `term` は、用語集のカードの `id`(`term-` を除いた部分)と合わせる。
- `level` は `basic` か `advanced`、`type` は `recall` か `choice`。
- `highlight` と `mask` には `marks` の `id` を並べる。`mask` で隠すラベルは、問題の答えで明かす。

## 出し方

- HTML の 1 ページにする。Artifact を使える環境なら Artifact として公開する。
- 図の SVG は `<img>` の data URI で埋め込む。インラインの SVG を並べると、記号の ID が衝突するためである。印の層はひな形が図の上に重ねる。

## 確かめること

- 図は `SKILL.md` の「描いたあとの確認」で確かめる。
- 印の範囲が図の部品と重なっているかを、「用語の場所を表示」で目で見る。
- 結論と分かったことの文を、セッションの記録と照合する。
- テストの正答と解説が、本文の事実と食い違っていないか。
- テストの操作(始める、光る・隠れる、答えを見る、選ぶ、発展へ進む、まとめ、用語へのリンク)を 1 回ずつ試す。
