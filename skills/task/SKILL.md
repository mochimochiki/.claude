# Taskスキル

実行モードで取り組む、1つの完結した仕事をタスクチケットにまとめる。
チケットは作業計画だけでなく、完了までの共有記録として更新する。

## 配置

配置先は次の優先順位で決める。

1. 指示された場所を使う。ローカルなのかGitHub Issueなのかを含む。
2. ワークスペース慣例に従う。`docs/tasks`、`tasks` など、実際の構成と命名に合わせる。
3. 1,2に該当しない場合、ユーザーに配置先を確認する。勝手に新しいディレクトリを増やさない。

ファイル名は慣例や既存規約に合わせる。規約が示されていない場合 `YYMMDD-NN_{タイトル}.md` とする。

## テンプレート

```md
# Task-YYMMDD-NN: {タイトル}

## WHY: Background
{なぜこのタスクをやるのか、1-3行}

## WHAT: Goal
{このタスクで何を達成するのか、1-3行}

## HOW: Design
{方針・設計。mermaidシーケンス図も可。要素は4以下。1画面内に収める。}

## Decisions
- {スコープ・前提・決定事項}

## Relevant files
- `{full/path/to/file}` — {変更・参照内容}

## Steps
- [ ] {タスクステップ}

## Gates
- [ ] {品質ゲート=完了条件}

## Review
<!-- reviewer記入 → coder対応 → reviewer✅ -->
**評価:** (⭐x → ⭐y → ✅承認 / ⚠️条件付き承認 / ❌差し戻し)

- [ ] 🔴 重大指摘の概要 (or 🟠 優先指摘の概要 / 🟡 推奨指摘の概要 / 🟢 任意指摘の概要)
  - 対応内容

## Notes
{エージェント間の情報共有・備考}
```

## 運用

- 実行前に `WHY`、`WHAT`、`HOW`、`Steps`、`Gates` を具体化する。
- 実行中は `Steps` と `Gates` を更新し、レビュー指摘と対応を `Review` に残す。

## ゲート

- レビュー欄にレビュー結果が記録されていること。
- 完了時は全項目 `[x]` にし、未完了項目を残したまま完了報告しない。
