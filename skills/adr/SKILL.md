# ADRスキル

見返す価値のある設計判断を、短い記録として残す。意思決定がない単純作業では作成しない。

## 配置

配置先は次の優先順位で決める。

1. ワークスペースにすでにあるADRファイルや同じ役割の記録を使う。`docs/ADR.md` など、実際の構成と命名に合わせる。
2. エージェントがこの仕事のために指定した配置を使う。
3. 1と2のどちらにも該当しない場合は、ユーザーに配置先を確認する。勝手に新しいファイルを増やさない。

## 運用

- 既存のADRがある場合は1ファイルに追記する。
- 新しい記録をファイルの先頭へ追加する。
- 背景、決定、理由はそれぞれ90文字以内を目安に簡潔に書く。
- ADRを作成しない場合も、タスクや設計書にその判断理由を残す。
- 保守：直前のADRが長文である場合、今回のADR記載とともにそのADRを要約するかどうかをユーザーに確認する。承認が得られたら要約する。

## テンプレート

~~~md
# Architectural Decision Record

## template
```
### ADR-YYMMDD-NN: {決定名}
**背景** : {決定に至った背景 — 90文字以内で簡潔に}
**決定** : {決定内容 — 90文字以内で簡潔に}
**理由** : {理由 — 90文字以内で簡潔に}
**備考** : {通常項目ごと省略。特記事項があれば記載。通常90文字以内で簡潔に}
```

## ADR

### ADR-YYMMDD-NN: {決定名}
...
~~~

## ゲート

- ADRに書く価値のある意思決定の記録であること。微細な判断やただの作業履歴は書かない。
- 各項目が90文字以内で簡潔に記載されていること
